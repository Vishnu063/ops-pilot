## Resolved failures and boundaries

Real tests caught a too-short observation window on a 0.25-CPU Python sample: two connection failures followed by HTTP 200 did not satisfy two consecutive successes. The practice configuration now explicitly uses five attempts; the original default remains three and the two-success rule is unchanged. The host port is explicit and stable across restart. An existing native lab also exposed a Python/Alpine wording change (`Address in use` versus `Address already in use`); matching now accepts both bind-specific messages while unrelated crashes remain unconfirmed faults. A pre-existing Playwright job was pinned to supported Ubuntu 24.04 after ubuntu-latest moved beyond its pinned browser version. Transient n8n anonymous-form failures were not accepted as a pass; subsequent full authenticated/anonymous form checks passed without weakening authentication.

Source checks ran locally where possible. This execution sandbox denies local TCP/Unix sockets; actual HTTP/browser/Docker/systemd/monitoring acceptance therefore ran on disposable GitHub runners. No production failures were injected. No AI-generated command or webhook can approve a mutation. K8sGPT uses a fixed scoped read-only argv and does not enable provider inference by default. No paid API or model download was introduced.

Prometheus/K8sGPT metadata screening identified Apache-2.0; Grafana is AGPL-3.0. Upstream servers/models were not vendored. Same-owner existing components remain pinned/reused in place; existing repositories without detected root licenses still need owner distribution review before external reuse. Model weights/provider terms are separate.

Remaining gates are explicit: actual customer authorization/access; Jenkins/Trivy and the existing pharmacy target; real cluster/GitOps/Helm/K8sGPT; Grafana/host exporter provisioning; controlled triggers for each resource/restart/rollout/error-rate policy; external log backend if desired; and full-stack 8 GB measurement. Source/read-only credentials and programmatic synthetic acceptance are not evidence of customer consent. All independently implemented integrations are optional and documented; standalone projects remain usable.
